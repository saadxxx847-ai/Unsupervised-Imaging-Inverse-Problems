# DDM4IP 组会进度汇报

**日期：** 2026-09-04  
**项目：** 在真实、不配对的 BDD100K 道路图像上验证 DDM4IP 三阶段去模糊流程。

## 1. 我们要解决什么问题？

现有清晰图和模糊图不是同一场景的一一对应照片，不能用“模糊图—清晰真值”直接监督训练。项目目标是先从数据中学习模糊机制，再用该机制恢复模糊图。

```text
模糊图 → Step 1：学习模糊图分布 → Step 2：学习模糊机制 → Step 3：去模糊预测图
清晰图 ────────────────────────────────┘
```

## 2. 已完成工作

- **运行环境：** 已在 Windows + RTX 2070 SUPER 上完成项目入口、CUDA、包导入与 PyTorch 兼容性修复和验证。
- **数据准备：** 从 BDD100K 中构建了只读硬链接视图：清晰图训练/验证为 **1565/174**，Q2/Q3 模糊图训练/验证为 **926/104**。原始图像未被改写。
- **实验配置：** Step 1、2、3 的 Hydra 配置可组合解析；完整单元测试曾达到 **12/12 通过**。
- **无真值边界：** Step 2 关闭配对验证；Step 3 仅计划输出重投影 L1/L2、预测图和估计核，不报告 PSNR、SSIM、LPIPS。
- **Step 3 预检：** 已提前发现并复现输入尺寸与结果溯源问题，避免在长时间实验中才失败。

## 3. 当前阻塞（尚未启动训练）

1. Step 3 配置要求 128×128 切块，但当前验证数据给出 64×64 patch；实际重建会发生 **64 与 32 像素尺寸不匹配**。
2. 当前输出文件只按序号命名，未记录原始文件名和切块坐标，结果不能可靠追溯到输入图像。
3. Step 1/2 尚未运行，因此没有可供 Step 3 使用的 flow checkpoint、kernel snapshot；DPIR/DRUNet 权重也尚未落地到项目缓存。

## 4. 下一步计划

1. 修复并测试 Step 3 的全图/完整切块几何，以及“输出—源图—坐标”manifest。
2. 验证不覆盖的计划任务运行器、日志、状态文件和配置快照。
3. 依次进行 Step 1 pilot → 完整 Step 1 → Step 2 pilot → 完整 Step 2；每阶段产物均独立做 SHA-256 核验。
4. 在 Step 2 产物和 DRUNet 权重核验后，先做单图 Step 3 GPU 回归，再决定 Step 3 pilot 与完整运行。

## 5. 当前结论

项目已完成“环境—数据—配置—关键风险预检”的基线准备，但**尚未产生可比较的去模糊实验结果**。当前最重要的是先保证 Step 3 的几何正确性和结果可追溯性，再进入耗时的三阶段实验。
