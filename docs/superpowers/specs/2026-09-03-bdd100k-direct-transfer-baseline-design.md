# BDD100K 真实异质不配对数据的直接迁移基线：设计说明

**日期：** 2026-09-03  
**状态：** 已获用户批准；尚未启动真实训练

## 1. 要回答的问题

在不改动论文核心网络、损失或三阶段流程的前提下，DDM4IP 能否在真实、同域但不配对且退化异质的 BDD100K 道路图像上完整运行，并产出可追溯、可诊断的恢复结果？

这是一条“直接迁移基线”，不是论文固定运动模糊、有配对真值实验的等价复现。它的目的，是建立后续改造的可信起点并定位最主要的失败模式。

## 2. 已知条件与结论边界

- 数据源为远端 `D:\DDM4IP-runtime\group-data\BDD100K_Blur_Sharp`：清晰图 1,739 张、模糊图 2,060 张，均为 1280×720 JPG；两侧不成对。
- 退化代理审计显示模糊集 Laplacian 方差 5–95 分位数为 20.35–164.29，跨度约 8 倍。因此数据不满足“共享固定 PSF”的理想假设。
- 清晰与模糊集均来自 BDD100K 道路域，仍可作为同域不配对的首轮压力测试。
- 不得对恢复图报告相对清晰真值的 PSNR、SSIM 或 LPIPS，也不得与论文 FFHQ 合成数值直接比较。
- 锐度代理上升不等于恢复成功；它可能来自伪纹理或过度锐化。

## 3. 固定范围

### 包含

1. 用现有审计 CSV 选择模糊代理分数的 Q2/Q3，并对清晰集和两个模糊层分别作确定性、按组分层的 90/10 划分。
2. 使用硬链接创建独立的数据视图，绝不改写原始图像或覆盖既有视图。
3. 按 DDM4IP 的 Step 1、Step 2、Step 3 原有顺序完成一次完整基线。
4. 保存可复跑配置、任务状态、追加式日志、检查点、输入/输出样例和评估摘要。
5. 记录并归类失败模式。

### 不包含

1. 超参数网格、数据筛选消融、多种模型或多官方场景的横向比较。
2. 把真实不配对数据伪装成有配对真值，或输出无根据的全参考指标。
3. 对原始数据、用户已有仓库修改或共享环境作覆盖、清理或 Git 提交。

## 4. 三阶段与数据流

```text
原始 clean 图 ──┐
                ├─ Step 2：学习与真实模糊分布相符的显式退化算子
原始 blurry 图 ─┘
        │
        ├─ Step 1：学习从观测模糊图出发的条件生成/恢复分布
        │
        └─ Step 3：结合已学习的退化算子与非盲恢复流程，恢复留出的模糊图
```

- **Step 1** 使用模糊图训练相应的条件生成/恢复部分。
- **Step 2** 使用数量可不同的独立 clean/noisy 训练目录；因两者不配对，设置 `training.max_val_batches=0`，不解释默认验证中的逐样本误差或配对图。
- **Step 3** 使用 noisy-only 数据集，确保 `batch.clean=None`，避免误计算全参考指标。
- 所有数据路径、随机种子、可改变的内存参数和输出位置由配置覆盖；论文的核心网络、损失和阶段顺序不作预先修改。

## 5. 数据视图设计

视图构建器输入为原始数据目录与已验证的代理审计 CSV，输出位于：

`D:\DDM4IP-runtime\group-data-views\BDD100K_Blur_Sharp`

其必须满足：

- 清晰图：1,739 张按固定种子分为 train/val，预计为 1,565/174 张。
- 模糊图：仅选择 Q2 和 Q3；2,060 张中预计选中 1,030 张，再按层分别作 90/10 划分，预计 noisy train/val 为 926/104 张。
- 每个文件均为同卷硬链接；`manifest.csv` 和 `summary.json` 保存具体清单、种子、选择规则和计数。
- 目标已存在时立即失败，绝不覆盖或混合旧视图。

在创建真实视图前，先运行 `tests/test_bdd100k_view_builder.py`。只有测试通过且目标路径仍不存在时才允许创建。

## 6. 时间预算与阶段门

总预算为最多三个独立的长运行时段，可在白天或夜间启动。三个阶段是独立任务；一个阶段失败、产物缺失或验证不通过时，不启动下一阶段。

### 6.1 短试验：只估时与验证流程

每个阶段先使用独立的 pilot 输出根目录运行达到首个真实优化/推理、日志写入、检查点或结果保存路径的最小短试验。pilot 不用于评估模型效果，且不能覆盖完整基线产物。

pilot 记录每阶段的实际步速、显存占用、首个检查点时间、输出大小和退出码。根据“原始配置目标步数 ÷ 实测有效步速”估算完整阶段时长。

若某阶段预计明显超过一个阶段运行窗口，停止在启动完整阶段之前，向用户报告估算和候选的明确缩短预算；不得静默缩短训练或让单阶段跨过三个窗口总预算。

### 6.2 完整基线：最多三个独立后台任务

| 阶段运行窗口 | 任务 | 启动门 | 产物门 |
| --- | --- | --- | --- |
| 第 1 阶段窗口 | 完整 Step 1 | 视图与 Step 1 pilot 均通过 | 完成状态、配置、日志和 Step 1 检查点齐全 |
| 第 2 阶段窗口 | 完整 Step 2 | Step 1 产物独立核验通过，Step 2 pilot 通过 | 完成状态、配置、日志和退化算子/检查点齐全 |
| 第 3 阶段窗口 | 完整 Step 3 与留出集恢复 | Step 2 产物独立核验通过，Step 3 pilot 通过 | 完成状态、配置、恢复结果和评估输入齐全 |

一个“阶段运行窗口”是每个阶段的预先估算上限，不是通过杀死任务强行实现的时限。任何超预算风险须在完整任务启动前处理。

## 7. 无人值守任务、状态与产物

每个 pilot 和完整阶段均由 `group-pc` 的 Windows 任务计划程序托管，不能依赖本机保持开启。任务仅使用已落地在远端的数据、仓库和缓存；若尚有本机到远端的传输，必须先完成远端落地及 SHA-256 核验。

完整基线的根目录使用唯一名称，例如：

`D:\DDM4IP-runtime\experiments\bdd100k-direct-transfer-20260903`

每个阶段的独立目录至少包含：

```text
stepN/
  status.json          # RUNNING / SUCCESS / FAILED
  task.log             # 追加式完整日志
  resolved-config.yaml # 实际解析后的配置快照
  command.txt          # 实际模块命令及进程级环境变量
  checkpoints/         # 训练检查点；不适用时说明原因
  outputs/             # 阶段输出或恢复图
  metrics/             # 阶段或最终评估摘要
```

状态文件至少记录：当前状态、当前步骤、更新时间、主机、Python 路径、仓库路径、运行根目录、日志路径、配置路径、输出路径、计划任务名、进程 ID（运行时）和退出码（结束后）。失败状态必须保留异常摘要与失败步骤。

任务启动后，助手只确认一次计划任务、远端进程、状态与日志正在更新；不持续轮询。用户可关闭本机，并在次日通过 VS Code Remote SSH 执行：

```powershell
Get-Content -Raw -LiteralPath 'D:\DDM4IP-runtime\experiments\bdd100k-direct-transfer-20260903\step1\status.json'
Get-Content -LiteralPath 'D:\DDM4IP-runtime\experiments\bdd100k-direct-transfer-20260903\step1\task.log' -Tail 50 -Wait
```

按 `Ctrl+C` 只停止日志跟随，不停止计划任务。用户通知任务结束后，助手再以新的远端命令独立验证退出码、文件存在性和结果一致性。

## 8. 评估与失败模式记录

对 Step 3 的留出模糊图，固定随机种子抽取并保存可复查样例：输入模糊图、恢复图、重退化图及必要的中间可视化。每份展示同时保留代表性成功样例和失败样例，不能只挑选最佳结果。

评估分为四类：

1. **重投影一致性：** 将恢复结果通过已学习退化算子生成重退化图，与观测模糊图计算并保存残差摘要。这衡量“模型的恢复与自身退化解释是否一致”，不等价于清晰真值质量。
2. **无参考质量检查：** 保存锐度、伪影和颜色/对比度的代理量，仅作辅助诊断，不单独用来宣布成功。
3. **固定盲评样例：** 以相同样例组比较输入与恢复，记录自然度、细节保留、伪纹理、过锐化、颜色偏移和残余模糊。
4. **失败归类：** 至少区分恢复不足、过度锐化/伪纹理、颜色或曝光偏移、局部/非均匀模糊失配、强退化样本崩溃、跨场景泛化差和运行/资源错误。

最终报告必须把“训练成功完成”与“图像恢复有实际改善”分开陈述。

## 9. 完成判据

这一轮在同时满足以下条件时完成：

1. 三阶段完整任务均有可验证的 `SUCCESS` 或被可解释的失败状态终止；没有未记录的中断。
2. 每阶段都保留实际配置、命令、日志、状态、检查点/输出和独立退出码核验。
3. Step 3 对固定留出样例产生保存的恢复和重退化结果。
4. 形成一份不使用配对真值指标的基线总结，明确最主要失败模式及其证据。
5. 工作日志更新为实际发生的事实，而非计划中的结果。

## 10. 风险与下一轮边界

最可能的科学风险是混合退化破坏了共享退化分布假设，导致学到的算子过于平均化，或在不同图像上产生不稳定恢复。最可能的工程风险是 8 GB GPU 显存、Windows 多进程、长任务中断和检查点衔接。

第一轮结束前不通过改变多个因素来掩盖这些风险。下一轮只能根据本轮已保存的失败证据，选择一个优先改动方向并与本基线严格对照。
